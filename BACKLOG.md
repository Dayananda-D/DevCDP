# DevCDP — Stabilisation Backlog

Origin: an audit of the session deck and handout against the shipped v4 `server.js`,
verified live against a real single-page application. 40 defects were catalogued,
plus two new requirements.

**Rule adopted:** every claim the tool makes is either true, or the claim is
removed. No silent failures — a failure must be impossible to mistake for success.

**Verification:** `npm test` → 34 offline + 26 installer + 87 integration checks against a
real Chrome and a fixture app. Every P0 below has a test that fails if it regresses.

**A later round came from running against a real application rather than the fixture**
(UI-5 to UI-9, EVAL-1, SRC-5, SRC-6, CAP-1, DBG-8, DBG-9, INPUT-1, CFG-7, COLLAB-5, LAUNCH-1, TEST-3, TEST-4). The fixture served one
script and one tidy object graph, so it could not expose search ranking, coverage
honesty, live-object evaluation, tabs the app opens for itself, an overlay outliving its
session, or a response cap that only held for flat lists. Two were spotted by looking at
the screen, which no test I had written could have done, and one — CAP-1 — was a
guarantee this backlog had already claimed to have delivered. The fixture was rebuilt to
have the shape of a real application: a vendor library, 24 modules, a window it opens
itself.
